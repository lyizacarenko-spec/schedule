# Автозвіт у дашборд задач

Коли Луіза дає тобі новий запит на роботу в цьому проєкті (наприклад "зроби
вебку для X", "виправ баг Y") — став цю задачу в дашборд одразу, на самому
початку роботи, зі статусом "in_progress". Не чекай завершення, щоб її
завести — інакше Луїза не побачить, що робота вже почалась.

Коли завершуєш роботу над задачею — постав той самий запит ще раз, але зі
статусом "done" (той самий текст `task`, щоб він зматчився з уже створеною
задачею, а не створив дублікат).

```bash
# на початку роботи над новим запитом
curl -X POST https://task-dashboard-backend-production.up.railway.app/api/quick-update \
  -H "Content-Type: application/json" \
  -H "x-pin: OWNER_PIN_ТУТ" \
  -d '{"updates":[{"project":"НАЗВА_ПРОЄКТУ","task":"КОРОТКИЙ_ОПИС_ЗАПИТУ","status":"in_progress"}]}'

# по завершенню — той самий task, інший статус
curl -X POST https://task-dashboard-backend-production.up.railway.app/api/quick-update \
  -H "Content-Type: application/json" \
  -H "x-pin: OWNER_PIN_ТУТ" \
  -d '{"updates":[{"project":"НАЗВА_ПРОЄКТУ","task":"КОРОТКИЙ_ОПИС_ЗАПИТУ","status":"done"}]}'
```

Правила:
- `project` — назва проєкту в дашборді (нечіткий пошук ILIKE). Якщо такого
  проєкту в дашборді ще нема — попроси Луїзу підтвердити назву, не вигадуй
  нову, і скажи їй, що для нового проєкту потрібно спершу додати запис owner'ом
  (кнопка «Додати проєкт» у дашборді), бо quick-update створює лише ЗАДАЧІ,
  не нові проєкти
- `task` — формулюй стисло і залиш ту саму фразу і на старті, і на фініші,
  інакше замість оновлення статусу створиться друга задача-дублікат
- `status` — "todo" / "in_progress" / "done"
- Заміни `OWNER_PIN_ТУТ` на реальний PIN (Луіза підставляє сама, в код
  репозиторію PIN не коммітити)
- Якщо curl повертає `{"error":"project_not_found"}` — проєкту з такою назвою
  нема в дашборді, звірся з Луїзою, а не вгадуй
- Роби це автоматично, без запиту дозволу щоразу — але одним реченням
  повідом Луїзі, що завів/закрив задачу в дашборді
